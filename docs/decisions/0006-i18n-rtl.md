# ADR-0006: Bilingual English/Arabic with full RTL

- Status: Proposed
- Date: 2026-10-24

## Decision
- Two first-class locales from the first screen: `en` (LTR) and `ar` (RTL). User preference stored on profile; tenant sets default.
- All text from message catalogs (ICU format) in `packages/i18n`; CI check fails on missing keys in either language.
- CSS uses logical properties only; lint rule bans `ml-*/mr-*/left-*/right-*` style physical utilities in components.
- Typography (revised 2026-10-24 with design v0.2): **Plus Jakarta Sans** (English UI) + **Readex Pro** (Arabic UI), with **Instrument Serif** / **Amiri** for the greeting display only. All SIL OFL, self-hosted (no Google Fonts CDN, so on-prem works offline). Tabular figures for numeric columns.
- Bilingual data fields (`name_en`, `name_ar`) for entities that appear on official documents.
- Playwright visual tests run each key screen in both directions.
- Server error messages return codes + parameters; the client localizes them (server never sends English-only sentences for UI).

## Consequences
- (+) Avoids an expensive retrofit; RTL bugs caught continuously.
- (−) Every component is designed and reviewed twice (LTR/RTL). Accepted as core to the Kuwaiti market.
- Arabic translations need native-speaker review before release; machine-drafted strings are marked as needing review.
